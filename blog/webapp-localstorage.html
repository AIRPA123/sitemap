브라우저 로컬 저장소란 무엇이며 언제 데이터가 사라질까

AIRPALAB 운영자 · 직접 개발 및 검수 · 2026-08-08 · 기술 분석

간단한 웹 도구는 서버 계정 없이 브라우저의 로컬 저장소(localStorage)에 데이터를 보관할 수 있습니다. AIRPALAB에서 직접 테스트한 데이터를 바탕으로 저장소가 작동하는 원리와 실제 한계를 확인해 봅니다.

AIRPALAB To-Do 데이터 실제 입력 테스트

웹 서비스에 회원가입 없이 할 일을 등록하면 데이터는 어디에 남을까요? 크롬(Chrome) 브라우저를 켜고 AIRPALAB To-Do 서비스에 직접 "애드센스 글 수정"이라는 할 일을 등록해 보았습니다.

입력 후 개발자 도구(F12)를 열어 Application → Local Storage 탭을 확인하면 아래와 같이 데이터가 실제 기기에 저장된 것을 볼 수 있습니다.

이 데이터는 인터넷 서버로 전송되지 않고 현재 사용 중인 브라우저에만 머물러 있습니다. 새로고침을 하거나 브라우저를 종료한 뒤 다음 날 다시 접속해도 데이터는 그대로 유지됩니다.

간단한 JavaScript 코드로 확인하기

개발자 도구의 Console 탭에서 직접 코드를 입력해 보면 로컬 저장소의 원리를 명확하게 이해할 수 있습니다.

// 1. 데이터 저장하기
localStorage.setItem("todo", "애드센스 글 수정");

// 2. 저장된 데이터 불러오기
const myTodo = localStorage.getItem("todo");
console.log(myTodo); // 출력: "애드센스 글 수정"

// 3. 데이터 삭제하기
localStorage.removeItem("todo");

이처럼 아주 간단한 코드로 동작하기 때문에 로그인 기능이 없는 가벼운 도구를 만들 때 유용하게 쓰입니다.

시크릿 모드와 사이트 데이터 삭제 테스트

로컬 저장소의 치명적인 단점은 '영구적이지 않다'는 것입니다. 실제 테스트 결과는 다음과 같습니다.

  • 시크릿 모드 접속: 브라우저 창을 닫는 순간 로컬 저장소의 데이터도 함께 증발합니다. 다시 접속해도 복구할 수 없습니다.
  • 사이트 데이터 삭제: 크롬 설정에서 '인터넷 사용 기록 삭제'를 하거나 개발자 도구에서 'Clear site data'를 누르면 저장된 정보가 모두 사라집니다.
  • 다른 브라우저 접속: 크롬에서 입력한 내용을 엣지(Edge)나 웨일(Whale) 브라우저에서 열면 데이터는 보이지 않습니다. 각 브라우저는 독립된 저장소를 사용하기 때문입니다.

안전한 사용을 위한 결론

로컬 저장소는 빠르고 편리하지만, 데이터의 주도권이 전적으로 브라우저 환경에 있습니다. AIRPALAB과 같이 가벼운 웹 도구를 사용할 때는 중요한 자료의 '유일한 원본'을 브라우저에만 보관하지 않도록 주의해야 합니다.
